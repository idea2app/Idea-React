# Tooltips

Custom replacement for browser tooltips—themed with CSS variables and positioned by Idea React’s `OverlayBox`.

## Overview

Hover the button below to see a tooltip. By default, the tooltip will appear above their trigger element (the child of `OverlayBox`).

<CodeExample>
    <OverlayBox title="Tooltip on top">
        <Button variant="solid" theme="secondary">
            Hover me
        </Button>
    </OverlayBox>
</CodeExample>

Things to know when using tooltips with `OverlayBox`:

- Provide a non-empty `title` so the tooltip has a meaningful accessible description.
- Specify `container="body"` to avoid rendering problems in more complex components (like our input groups, button groups, etc).
- Triggering tooltips on hidden elements will not work.
- Tooltips for `disabled` elements must be triggered on a wrapper element.
- When triggered from hyperlinks that span multiple lines, tooltips will be centered. Use `white-space: nowrap;` on your `<a>`s to avoid this behavior.
- Unmount `OverlayBox` together with its trigger so the tooltip and positioning listeners are cleaned up.
- Tooltips can be triggered thanks to an element inside a shadow DOM.

Got all that? Great, let’s see how they work with some examples.

Pass rich content as React nodes instead of injecting untrusted HTML. React escapes text content by default.

The animation effect of this component is dependent on the `prefers-reduced-motion` media query.

Use the `title` prop on `OverlayBox`, rather than the native `title` attribute on the trigger, to avoid duplicate browser tooltips.

### Custom tooltips

You can customize the appearance of tooltips using [CSS variables][1]. We pass a CSS module class through `overlayClassName` to scope our custom appearance and use it to override a local CSS variable.

<CodeExample>
    <OverlayBox
        title="This top tooltip is themed via CSS variables."
        overlayClassName={styles.tooltip}
    >
        <Button variant="solid" theme="secondary">
            Custom tooltip
        </Button>
    </OverlayBox>
</CodeExample>

### Responsive placement

Change placement at different breakpoints using `responsivePlacement={{ md: 'right', lg: 'bottom' }}`, where each breakpoint is one of `sm`, `md`, `lg`, `xl`, or `2xl`.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <OverlayBox
            title="Responsive tooltip"
            placement="top"
            responsivePlacement={{ md: 'right', lg: 'bottom' }}
        >
            <Button variant="solid" theme="secondary">
                Top → md:right → lg:bottom
            </Button>
        </OverlayBox>
        <OverlayBox title="Responsive tooltip" placement="left" responsivePlacement={{ lg: 'top' }}>
            <Button variant="solid" theme="secondary">
                Left → lg:top
            </Button>
        </OverlayBox>
    </div>
</CodeExample>

Resize your browser to see the tooltip placement change at different breakpoints.

### Interactive tooltips

Move the pointer onto the tip to reach interactive content inside it, such as a link. The tooltip stays open while the pointer is over the trigger or the tip. It hides when the pointer leaves both, or when you press the <kbd>Escape</kbd> key. This helps satisfy the [WCAG 1.4.13 “Content on Hover or Focus”][2] success criterion.

<CodeExample>
    <OverlayBox
        title={
            <>
                Need more details? <a href="#interactive-tooltips">Read the documentation</a>.
            </>
        }
    >
        <Button variant="solid" theme="secondary">
            Interactive tooltip
        </Button>
    </OverlayBox>
</CodeExample>

### Disabled elements

Elements with the `disabled` attribute aren’t interactive, meaning users cannot focus, hover, or click them to trigger a tooltip (or popover). As a workaround, you’ll want to trigger the tooltip from a wrapper `<div>` or `<span>`, ideally made keyboard-focusable using `tabindex="0"`.

<CodeExample>
    <OverlayBox title="Disabled tooltip">
        <span className="d-inline-block rounded-3" tabIndex={0}>
            <Button variant="solid" theme="primary" disabled>
                Disabled button
            </Button>
        </span>
    </OverlayBox>
</CodeExample>

## Usage

### Delegated tooltips

To enable tooltips on many triggers at once—including elements added to the DOM later—render an `OverlayBox` for each trigger in your React list. React mounts and removes the overlays with their triggers; no selector-based plugin initialization is needed.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        {['First', 'Second', 'Third'].map(label => (
            <OverlayBox key={label} title={`${label} tooltip`}>
                <Button variant="solid" theme="secondary">
                    {label} trigger
                </Button>
            </OverlayBox>
        ))}
    </div>
</CodeExample>

### Markup

Wrap the trigger in `OverlayBox` and provide its `title`. It renders the `Tooltip` markup, places it relative to the trigger, and connects it with `aria-describedby`.

**Keep tooltips accessible to keyboard and assistive technology users** by only adding them to HTML elements that are traditionally keyboard-focusable and interactive (such as links or form controls). While other HTML elements can be made focusable by adding `tabIndex={0}`, this can create annoying and confusing tab stops on non-interactive elements for keyboard users, and most assistive technologies currently do not announce tooltips in this situation. Additionally, do not rely solely on `hover` as the trigger for your tooltips as this will make them impossible to trigger for keyboard users.

A shown tooltip can be dismissed by pressing the <kbd>Escape</kbd> key, helping satisfy the [WCAG 1.4.13 “Content on Hover or Focus”][2] success criterion. The tooltip also stays open while the pointer moves onto the tip, so users can reach interactive content inside it. As with dropdown menus, a tooltip shown inside a dialog is dismissed on its own: the first <kbd>Escape</kbd> closes the tooltip and a subsequent one closes the dialog.

### Options

| `OverlayBox` prop     | Default           | Description                                                           |
| --------------------- | ----------------- | --------------------------------------------------------------------- |
| `title`               | required          | Tooltip text or rich React content.                                   |
| `trigger`             | hover and focus   | Choose `"click"`, `"hover"`, `"focus"`, or a combination as an array. |
| `placement`           | `"top"`           | Preferred direction: `top`, `right`, `bottom`, or `left`.             |
| `responsivePlacement` | —                 | Override direction at named breakpoints.                              |
| `container`           | alongside trigger | A selector, DOM element, or callback returning an element.            |
| `delay`               | `0`               | Show/hide delay in milliseconds, or `{ show: 500, hide: 100 }`.       |
| `offset`              | `8`               | Distance from the trigger, or a `[crossAxis, mainAxis]` pair.         |
| `padding`             | `8`               | Viewport inset for overflow avoidance.                                |
| `flip`                | `true`            | Flip direction when space is constrained.                             |
| `overlayClassName`    | —                 | Apply a CSS module class to the tooltip.                              |
