# Popover

Small, contextual overlays for displaying custom content and information via JavaScript.

## Overview

Click the button below to show and close a popover.

<CodeExample>
    <OverlayBox
        title="Popover title"
        detail="This is the popover content—make it as long as you want."
        trigger="click"
    >
        <Button variant="solid" theme="secondary">
            Toggle popover
        </Button>
    </OverlayBox>
</CodeExample>

Things to know when using popovers with `OverlayBox`:

- Provide meaningful `title` and `detail` content; use `detail` for the popover body.
- Specify `container="body"` to avoid rendering problems in more complex components (like our input groups, button groups, etc).
- Triggering popovers on hidden elements will not work.
- Popovers for `disabled` elements must be triggered on a wrapper element.
- When triggered from anchors that wrap across multiple lines, popovers will be centered between the anchors’ overall width. Use `.text-nowrap` on your `<a>`s to avoid this behavior.
- Unmount `OverlayBox` together with its trigger so the popover and positioning listeners are cleaned up.
- Popovers can be triggered thanks to an element inside a shadow DOM.

Pass rich content as React nodes instead of injecting untrusted HTML. React escapes text content by default.

The animation effect of this component is dependent on the `prefers-reduced-motion` media query.

Keep reading to see how popovers work with some examples.

## Examples

### Live demo

Titles are set via `title` and body content is set via `detail` on `OverlayBox`.

Use the `title` prop on `OverlayBox`, rather than the native `title` attribute on the trigger, to avoid duplicate browser tooltips.

<CodeExample>
    <OverlayBox
        title="Popover title"
        detail="And here’s some amazing content. It’s very engaging. Right?"
        trigger="click"
    >
        <Button variant="solid" theme="secondary">
            Toggle popover
        </Button>
    </OverlayBox>
</CodeExample>

### Placement

Set `placement` to change the direction. Four options are available: top, right, bottom, and left. Directions are mirrored when using Bootstrap in RTL.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <OverlayBox
            title="Popover on left"
            detail="And here’s some amazing content. It’s very engaging. Right?"
            trigger="click"
            placement="left"
        >
            <Button variant="solid" theme="secondary">
                Popover on left
            </Button>
        </OverlayBox>
        <OverlayBox
            title="Popover on top"
            detail="And here’s some amazing content. It’s very engaging. Right?"
            trigger="click"
            placement="top"
        >
            <Button variant="solid" theme="secondary">
                Popover on top
            </Button>
        </OverlayBox>
        <OverlayBox
            title="Popover on bottom"
            detail="And here’s some amazing content. It’s very engaging. Right?"
            trigger="click"
            placement="bottom"
        >
            <Button variant="solid" theme="secondary">
                Popover on bottom
            </Button>
        </OverlayBox>
        <OverlayBox
            title="Popover on right"
            detail="And here’s some amazing content. It’s very engaging. Right?"
            trigger="click"
            placement="right"
        >
            <Button variant="solid" theme="secondary">
                Popover on right
            </Button>
        </OverlayBox>
    </div>
</CodeExample>

### Responsive placement

Change placement at different breakpoints using `responsivePlacement={{ md: 'right', lg: 'bottom' }}`, where each breakpoint is one of `sm`, `md`, `lg`, `xl`, or `2xl`.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <OverlayBox
            title="Popover title"
            detail="And here’s some amazing content. It’s very engaging. Right?"
            trigger="click"
            placement="top"
            responsivePlacement={{ md: 'right', lg: 'bottom' }}
        >
            <Button variant="solid" theme="secondary">
                Top → md:right → lg:bottom
            </Button>
        </OverlayBox>
        <OverlayBox
            title="Popover title"
            detail="And here’s some amazing content. It’s very engaging. Right?"
            trigger="click"
            placement="left"
            responsivePlacement={{ lg: 'top' }}
        >
            <Button variant="solid" theme="secondary">
                Left → lg:top
            </Button>
        </OverlayBox>
    </div>
</CodeExample>

Resize your browser to see the popover placement change at different breakpoints.

### Custom `container`

When you have some styles on a parent element that interfere with a popover, you’ll want to specify a custom `container` so that the popover’s HTML appears within that element instead. This is common in responsive tables, input groups, and the like.

<CodeExample>
    <OverlayBox
        title="Popover title"
        detail="And here’s some amazing content. It’s very engaging. Right?"
        trigger="click"
        container="body"
    >
        <Button variant="solid" theme="secondary">
            Popover in body
        </Button>
    </OverlayBox>
</CodeExample>

Another situation where you’ll want to set an explicit custom `container` are popovers inside a [dialog][1], to make sure that the popover itself is appended to the dialog. This is particularly important for popovers that contain interactive elements – dialogs will trap focus, so unless the popover is a child element of the dialog, users won’t be able to focus or activate these interactive elements.

<CodeExample>
    <DialogDemo id="popoverContainerDialog" label="Popover inside dialog" title="Popover container">
        <OverlayBox
            title="Popover title"
            detail="This popover stays in the dialog’s top layer."
            trigger="click"
            container="#popoverContainerDialog"
        >
            <Button variant="solid" theme="secondary">
                Toggle popover
            </Button>
        </OverlayBox>
    </DialogDemo>
</CodeExample>

### Custom popovers

You can customize the appearance of popovers using [CSS variables][2]. We pass a CSS module class through `overlayClassName` to scope our custom appearance and use it to override some of the local CSS variables.

<CodeExample>
    <OverlayBox
        title="Custom popover"
        detail="This popover is themed via CSS variables."
        trigger="click"
        placement="right"
        overlayClassName={styles.popover}
    >
        <Button variant="solid" theme="secondary">
            Custom popover
        </Button>
    </OverlayBox>
</CodeExample>

### Dismiss on next click

Use the `focus` trigger to dismiss popovers on the user’s next click of an element other than the toggle element.
**Clicks and focus inside the popover itself do not dismiss it**, so users can select text or use controls in the content.

**Dismissing on next click requires specific HTML for proper cross-browser and cross-platform behavior.** For an anchor trigger, include a [`tabindex`][3].

<CodeExample>
    <OverlayBox
        title="Dismissible popover"
        detail="And here’s some amazing content. It’s very engaging. Right?"
        trigger="focus"
    >
        <Button href="#dismiss-on-next-click" tabIndex={0} variant="solid" theme="secondary">
            Dismissible popover
        </Button>
    </OverlayBox>
</CodeExample>

A shown popover can also be dismissed by pressing the <kbd>Escape</kbd> key. As with dropdown menus, a popover shown inside a dialog is dismissed on its own: the first <kbd>Escape</kbd> closes the popover and a subsequent one closes the dialog.

### Disabled elements

Elements with the `disabled` attribute aren’t interactive, meaning users cannot hover or click them to trigger a popover (or tooltip). As a workaround, you’ll want to trigger the popover from a wrapper `<div>` or `<span>`, ideally made keyboard-focusable using `tabindex="0"`.

For disabled popover triggers, you may also prefer `trigger={["hover", "focus"]}` so that the popover appears as immediate visual feedback to your users as they may not expect to _click_ on a disabled element.

<CodeExample>
    <OverlayBox title="Disabled popover" detail="Disabled popover" trigger={['hover', 'focus']}>
        <span className="d-inline-block rounded-3" tabIndex={0}>
            <Button variant="solid" theme="primary" disabled>
                Disabled button
            </Button>
        </span>
    </OverlayBox>
</CodeExample>

## Usage

**Keep popovers accessible to keyboard and assistive technology users** by only adding them to HTML elements that are traditionally keyboard-focusable and interactive (such as links or form controls). While other HTML elements can be made focusable by adding `tabIndex={0}`, this can create annoying and confusing tab stops on non-interactive elements for keyboard users, and most assistive technologies currently do not announce popovers in this situation. Additionally, do not rely solely on `hover` as the trigger for your popovers as this will make them impossible to trigger for keyboard users.

Avoid adding an excessive amount of rich content in popovers. Once popovers are displayed, their content is tied to the trigger element with the `aria-describedby` attribute, causing all of the popover’s content to be announced to assistive technology users as one long, uninterrupted stream.

Popovers do not manage keyboard focus order, and their placement can be random in the DOM, so be careful when adding interactive elements (like forms or links), as it may lead to an illogical focus order or make the popover content itself completely unreachable for keyboard users. In cases where you must use these elements, consider using a dialog instead.

### Options

| `OverlayBox` prop     | Default           | Description                                                                                                |
| --------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------- |
| `title`               | required          | Popover heading as a React node.                                                                           |
| `detail`              | —                 | Popover body as a React node. Without it, `OverlayBox` renders a tooltip.                                  |
| `trigger`             | hover and focus   | Use `"click"` for the click-to-toggle examples, `"focus"` to dismiss on blur, or an array of triggers.     |
| `placement`           | `"top"`           | Preferred direction: `top`, `right`, `bottom`, or `left`.                                                  |
| `responsivePlacement` | —                 | Override direction at named breakpoints.                                                                   |
| `container`           | alongside trigger | A selector, DOM element, or callback returning an element. Keep dialog overlays in the dialog’s top layer. |
| `delay`               | `0`               | Show/hide delay in milliseconds, or `{ show: 500, hide: 100 }`.                                            |
| `offset`              | `12`              | Distance from the trigger, or a `[crossAxis, mainAxis]` pair.                                              |
| `padding`             | `8`               | Viewport inset for overflow avoidance.                                                                     |
| `flip`                | `true`            | Flip direction when space is constrained.                                                                  |
| `overlayClassName`    | —                 | Apply a CSS module class to the popover.                                                                   |
