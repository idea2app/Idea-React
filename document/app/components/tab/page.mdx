# Tabs

Switch between related content panels using accessible tab controls.

## Nav tabs

Wrap `Tab` elements in `Tabs`. Each tab has a unique `eventKey`, a navigation `label`, and panel
content passed through `children`. The container's `id` keeps tab and panel relationships unique
on the page. Control selection with `activeKey`, or initialize it with `defaultActiveKey`.

<CodeExample>
    <Tabs id="account-tabs" aria-label="Account settings">
        <Tab eventKey="overview" label="Overview">
            Account summary and recent activity.
        </Tab>
        <Tab eventKey="security" label="Security">
            Review sign-in and security settings.
        </Tab>
        <Tab eventKey="disabled" label="Disabled" disabled>
            This panel is unavailable.
        </Tab>
    </Tabs>
</CodeExample>

## Pills and vertical tabs

Set `variant="pills"` for pill navigation. Use `orientation="vertical"` to stack the tab list; arrow
keys then follow the vertical direction.

<CodeExample>
    <Tabs id="project-tabs" variant="pills" orientation="vertical" aria-label="Project sections">
        <Tab eventKey="details" label="Details">
            Project description and ownership.
        </Tab>
        <Tab eventKey="activity" label="Activity">
            Recent project updates.
        </Tab>
        <Tab eventKey="members" label="Members">
            People with access to this project.
        </Tab>
    </Tabs>
</CodeExample>

## List groups and instant panels

`variant="list-group"` uses list-group styling. Panels fade in by default; set `fade={false}` for
instant switching.

<CodeExample>
    <Tabs id="project-list-tabs" variant="list-group" fade={false}>
        <Tab eventKey="details" label="Details">
            Project description and ownership.
        </Tab>
        <Tab eventKey="activity" label="Activity">
            Recent project updates.
        </Tab>
        <Tab eventKey="members" label="Members">
            People with access to this project.
        </Tab>
    </Tabs>
</CodeExample>

## Accessibility

The wrapper renders native buttons with tab, tablist, and tabpanel roles, paired IDs and labels,
selected state, and roving focus. Use Left/Right for horizontal tabs, Up/Down for vertical tabs, and
Home/End for the first/last enabled tab. Disabled tabs are skipped. The active panel is focusable
for keyboard users.

Tab panels should not contain menus: a trigger hidden inside a closed panel is difficult to discover
and does not fit the standard tabs accessibility pattern.
