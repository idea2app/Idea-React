# Dialog

A modern component built on the native `<dialog>` element with built-in accessibility and backdrop support that replaces the old Modal component.

## How it works

The Dialog component leverages the browser’s native `<dialog>` element, providing built-in accessibility features, focus management, and backdrop handling without the complexity of custom implementations.

Key features of the native dialog:

- **Modal or inline** via `showModal()` / `show()` — `modal: true` (default) promotes the dialog to the browser’s top layer with a backdrop and focus trapping; `modal: false` renders it inline.
- **Built-in backdrop** using the `::backdrop` pseudo-element (modal only); set `backdrop: "static"` to lock clicks outside, or `backdrop: false` to hide it.
- **Escape key handling** closes the dialog by default; set `keyboard: false` to disable.
- **Accessibility** — focus is trapped inside modal dialogs and returned to the trigger on close, with native `<dialog>` ARIA semantics.
- **Animated open and close** — circumvent browser restrictions by using a `.hiding` class to keep dialogs in the top layer during close so the exit transition (including `::backdrop`) are animated properly.

The animation effect of this component is dependent on the `prefers-reduced-motion` media query.

## Without JavaScript

Supported browsers can open and close a dialog with the [Invoker Commands API][1]—no Bootstrap JavaScript required. Set `commandFor` to the dialog’s `id`, use `command="show-modal"` to open, and `command="close"` to dismiss.

The Invoker Commands API is not supported in all browsers. For guaranteed support, use React-controlled `open` and `onClose`, as in the examples above, when you need wrapper options, events, or animated close.

<DocumentCodeExample>
    <Button
        variant="solid"
        theme="primary"
        {...{ commandfor: 'invokerDialog', command: 'show-modal' }}
    >
        Open dialog
    </Button>
    <NativeDialog id="invokerDialog" aria-labelledby="invokerDialogTitle">
        <DialogHeader>
            <DialogTitle id="invokerDialogTitle">Invoker Commands</DialogTitle>
            <CloseButton
                aria-label="Close"
                {...{ commandfor: 'invokerDialog', command: 'close' }}
            />
        </DialogHeader>
        <DialogBody>
            <p>
                This dialog opens with <code>command="show-modal"</code> and closes with{' '}
                <code>command="close"</code>. No Bootstrap JavaScript is involved.
            </p>
        </DialogBody>
        <DialogFooter>
            <Button
                variant="solid"
                theme="secondary"
                {...{ commandfor: 'invokerDialog', command: 'close' }}
            >
                Close
            </Button>
        </DialogFooter>
    </NativeDialog>
</DocumentCodeExample>

## Overlays

Tooltips, popovers, and toasts all work inside dialogs, but require some extra care. Since dialogs render in the browser’s top layer, overlays appended to `<body>` will appear behind the dialog. Keep `OverlayBox` inside the dialog, or set its `container` to the dialog element, so tooltips and popovers render inside it. Toasts already work as long as they’re placed in the dialog markup.

Tooltips, popovers, toasts, and menus all work inside modal dialogs. Modal dialogs use `showModal()`, which promotes the dialog to the browser’s top layer -- a special rendering layer above everything else on the page.

## Swapping dialogs

When a toggle trigger is inside an open dialog, clicking it will **swap** dialogs—opening the new one before closing the current. This ensures the backdrop stays visible throughout the transition with no flash. The React demo coordinates the two `open` props rather than using data-attribute triggers.

## Non-modal dialogs

By default, dialogs open as modals using the browser-native `showModal()` method. You can also open dialogs as non-modal using `show()` by setting `modal` to `false`. Non-modal dialogs:

- Have no backdrop
- Don’t trap focus
- Don’t block interaction with the rest of the page
- Don’t render in the browser’s top layer
- Still respond to Escape key (if `keyboard: true`)

<DocumentCodeExample source="document/component/Document/DialogDemo.tsx">
    <DocumentDialogDemo
        label="Open non-modal dialog"
        title="Non-modal dialog"
        saveLabel="Save changes"
        modal={false}
    >
        This dialog doesn’t block interaction with the rest of the page.
    </DocumentDialogDemo>
</DocumentCodeExample>

Use `modal={false}` to create a non-modal `NativeDialog`.

| Large       | `size="lg"` | `800px`          |

## JavaScript behavior

Control `NativeDialog` with `open`; update application state from `onClose`. The wrapper handles the browser’s native dialog methods and focus restoration.

### Options

| Prop        | Default  | Description                                                                                               |
| ----------- | -------- | --------------------------------------------------------------------------------------------------------- |
| `modal`     | `true`   | Open with a backdrop, focus trapping, and top-layer rendering.                                            |
| `backdrop`  | `true`   | Close on an outside click; `"static"` keeps the backdrop without outside dismissal, and `false` hides it. |
| `keyboard`  | `true`   | Close when Escape is pressed.                                                                             |
| `scroll`    | `false`  | Allow the document body to scroll.                                                                        |
| `animation` | `"fade"` | Choose `fade`, `instant`, `slide-down`, or `slide-up`.                                                    |

### Events

Native `onCancel` and `onClose` callbacks are forwarded. `onClose` runs when the native dialog closes, including after an animated close.
