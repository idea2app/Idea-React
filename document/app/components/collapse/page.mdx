# Collapse

Toggle the visibility of content across your project with a few classes and our JavaScript plugins.

## How it works

The collapse JavaScript plugin is used to show and hide content. Buttons or anchors are used as triggers that are mapped to specific elements you toggle. The plugin only adds and removes `.show`—the CSS animates the size from `0` to the content size. Given how CSS handles animations, you cannot use `padding` on a `.collapse` element. Instead, use the class as an independent wrapping element.

The animation needs [`interpolate-size`][1]. Browsers without it open and close the element at once. See [Transitions][2] to change the timing or to remove it.

> The animation effect depends on the `prefers-reduced-motion` media query. See the [reduced motion accessibility guidance][3].

## Example

Click the buttons below to show and hide another element via class changes:

- `.collapse` hides content
- `.collapse.show` shows content

Generally, we recommend a button trigger: use `CollapseToggle` with a `target` selector. While not recommended from a semantic point of view, passing `href` also renders an anchor trigger. The component manages the collapse behavior and accessibility attributes.

<DocumentCodeExample>
    <p className="d-inline-flex flex-wrap gap-1">
        <CollapseToggle
            target="#collapseExample"
            variant="solid"
            theme="primary"
            href="#collapseExample"
            role="button"
            aria-expanded="false"
            aria-controls="collapseExample"
        >
            {' Link with href '}
        </CollapseToggle>

        <CollapseToggle
            target="#collapseExample"
            variant="solid"
            theme="primary"
            type="button"
            aria-expanded="false"
            aria-controls="collapseExample"
        >
            {' Button with data-bs-target '}
        </CollapseToggle>
    </p>

    <Collapse id="collapseExample">
        <Card body>
            {
                ' Some placeholder content for the collapse component. This panel is hidden by default but revealed when the user activates the relevant trigger. '
            }
        </Card>
    </Collapse>

</DocumentCodeExample>

## Horizontal

The collapse component supports horizontal collapsing. Set `horizontal` to transition the inline size instead of the block size, and set a `width` on the immediate child element. Use inline styles or our [width utilities][4].

> Please note that while the example below has a `min-height` set to avoid excessive repaints in our docs, this is not explicitly required. **Only the `width` on the child element is required.**

<DocumentCodeExample>
    <p>
        <CollapseToggle
            target="#collapseWidthExample"
            variant="solid"
            theme="primary"
            type="button"
            aria-expanded="false"
            aria-controls="collapseWidthExample"
        >
            {' Toggle width collapse '}
        </CollapseToggle>
    </p>

    <div style={{ minHeight: '140px' }} className="overflow-auto">
        <Collapse horizontal id="collapseWidthExample">
            <Card style={{ width: '300px' }} body>
                {
                    ' This is some placeholder content for a horizontal collapse. It’s hidden by default and shown when triggered. '
                }
            </Card>
        </Collapse>
    </div>

</DocumentCodeExample>

## Multiple toggles and targets

A `CollapseToggle` can show and hide multiple elements by referencing them with a selector in its `target` prop.
Conversely, multiple triggers can show and hide the same element if they each reference it with their `target` prop.

<DocumentCodeExample>
    <p className="d-inline-flex flex-wrap gap-1">
        <CollapseToggle
            target="#multiCollapseExample1"
            variant="solid"
            theme="primary"
            href="#multiCollapseExample1"
            role="button"
            aria-expanded="false"
            aria-controls="multiCollapseExample1"
        >
            {'Toggle first element'}
        </CollapseToggle>

        <CollapseToggle
            target="#multiCollapseExample2"
            variant="solid"
            theme="primary"
            type="button"
            aria-expanded="false"
            aria-controls="multiCollapseExample2"
        >
            {'Toggle second element'}
        </CollapseToggle>

        <CollapseToggle
            target=".multi-collapse"
            variant="solid"
            theme="primary"
            type="button"
            aria-expanded="false"
            aria-controls="multiCollapseExample1 multiCollapseExample2"
        >
            {'Toggle both elements'}
        </CollapseToggle>
    </p>

    <Row>
        <Col>
            <Collapse id="multiCollapseExample1" className="multi-collapse">
                <Card body>
                    {
                        ' Some placeholder content for the first collapse component of this multi-collapse example. This panel is hidden by default but revealed when the user activates the relevant trigger. '
                    }
                </Card>
            </Collapse>
        </Col>

        <Col>
            <Collapse id="multiCollapseExample2" className="multi-collapse">

## Accessibility

Be sure to add `aria-expanded` to the control element. This attribute explicitly conveys the current state of the collapsible element tied to the control to screen readers and similar assistive technologies. If the collapsible element is closed by default, the attribute on the control element should have a value of `aria-expanded="false"`. If you’ve set the collapsible element to be open by default using the `show` class, set `aria-expanded="true"` on the control instead. The plugin will automatically toggle this attribute on the control based on whether or not the collapsible element has been opened or closed (via JavaScript, or because the user triggered another control element also tied to the same collapsible element). If the control element’s HTML element is not a button (e.g., an `<a>` or `<div>`), the attribute `role="button"` should be added to the element.

`CollapseToggle` keeps `aria-expanded` and `aria-controls` synchronized with the targeted elements.

If your control element is targeting a single collapsible element – i.e. the `data-bs-target` attribute is pointing to an `id` selector – you should add the `aria-controls` attribute to the control element, containing the `id` of the collapsible element. Modern screen readers and similar assistive technologies make use of this attribute to provide users with additional shortcuts to navigate directly to the collapsible element itself.

Note that Bootstrap’s current implementation does not cover the various _optional_ keyboard interactions described in the [ARIA Authoring Practices Guide accordion pattern][5] - you will need to include these yourself with custom JavaScript.

## CSS

### Variables

The collapse transition is controlled by CSS custom properties:

```css
.collapse {
    --bs-transition-collapse-property: block-size, display;
    --bs-transition-collapse-duration: 0.35s;
    --bs-transition-collapse-timing: ease;
}
```

### Classes

Collapse transition classes are shared with accordion in Bootstrap's transition stylesheet. `.collapse` hides the content and `.collapse.show` reveals it; `.collapse-horizontal` changes the animated axis to inline size. The component applies these classes through its visibility and `horizontal` props.

## Usage

The component adds or removes `.show` to control visibility; CSS handles the transition. Initialization and cleanup are automatic.

### Options

| Name          | Type    | Default | Description                                                                            |
| ------------- | ------- | ------- | -------------------------------------------------------------------------------------- |
| `defaultOpen` | boolean | `false` | Initial visibility of an uncontrolled collapse.                                        |
| `open`        | boolean | —       | Controlled visibility.                                                                 |
| `horizontal`  | boolean | `false` | Animate inline size rather than block size.                                            |
| `parent`      | string  | —       | Parent selector for accordion-like behavior: opening one collapse closes its siblings. |

Set `parent` on the collapsible area, not on its trigger. For native details-based disclosure groups, see [Accordion][6].

### Events

Use `onOpenChange(open)` to respond to visibility changes, or to update the state backing a controlled `open` prop.
