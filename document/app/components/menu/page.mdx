# Menu

Toggle contextual menus and custom overlays for lists of buttons, links, forms, and other custom content.

## Overview

Toggle menus with buttons whenever possible. Here’s an example using an Idea React button:

<CodeExample>
    <Menu label="Menu button">
        <MenuItem href="#menu-items">Action</MenuItem>
        <MenuItem href="#menu-items">Another action</MenuItem>
        <MenuItem href="#menu-items">Something else here</MenuItem>
    </Menu>
</CodeExample>

Menus are toggleable, contextual overlays for displaying lists of links and more. They’re made interactive by the `Menu` wrapper. Positioning updates when the viewport or trigger geometry changes. They’re toggled by clicking, not by hovering; this is [an intentional design decision][1].

## Examples

`Menu` uses the recommended `<button>` element for its toggle. Upstream also demonstrates an anchor toggle with `role="button"`; the current wrapper intentionally exposes a button toggle instead.

Use [button groups][2] to create split button menus where the menu is displayed when a secondary button is clicked.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <Menu label="Menu button">
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
        <ButtonGroup>
            <Button variant="solid" theme="secondary">
                Split
            </Button>
            <Menu
                split
                label={
                    <>
                        <Icon name="chevron-expand" />
                        <span className="visually-hidden">Toggle menu</span>
                    </>
                }
                toggleProps={{ variant: 'solid', theme: 'secondary' }}
            >
                <MenuItem href="#menu-items">Action</MenuItem>
                <MenuItem href="#menu-items">Another action</MenuItem>
                <MenuItem href="#menu-items">Something else here</MenuItem>
                <MenuDivider />
                <MenuItem href="#examples">Separated link</MenuItem>
            </Menu>
        </ButtonGroup>
    </div>
</CodeExample>

## Placement

Use `placement` on `Menu` to control where the menu appears.

- **Physical placements:** `top-start`, `top-end`, `bottom-start`, `bottom-end`, `left-start`, `left-end`, `right-start`, `right-end` — fixed directions regardless of text direction.
- **Edge alignment:** the `-start` and `-end` suffixes select an edge of the trigger. The wrapper does not expose upstream logical `start`/`end` side placements or automatically mirror placement in RTL.

Use both a physical direction and an alignment, such as `bottom-start` or `right-end`.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <Menu label="top-start" placement="top-start">
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>

### Responsive

Change placement at different breakpoints using `responsivePlacement={{ md: 'right', lg: 'bottom' }}`, where each breakpoint is one of `sm`, `md`, `lg`, `xl`, or `2xl`. Multiple breakpoints can be combined in the `responsivePlacement` object.

For example, `placement="bottom-start" responsivePlacement={{ md: "bottom-end", lg: "right-start" }}` will:

- Show the menu at `bottom-start` on small screens (default)
- Switch to `bottom-end` at the `md` breakpoint
- Switch to `right-start` at the `lg` breakpoint

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <Menu
            label="Bottom start → md:bottom-end"
            placement="bottom-start"
            responsivePlacement={{ md: 'bottom-end' }}
        >
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
        <Menu
            label="Bottom → lg:right"
            placement="bottom-start"
            responsivePlacement={{ lg: 'right-start' }}
        >
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
    </div>
</CodeExample>

Resize your browser window to see the placement change at different breakpoints.

## Submenus

Create nested menus with `MenuSubmenu`. Submenus support hover and click activation, keyboard navigation, and viewport-aware positioning. Submenus currently fly out to the side; the upstream small-screen stacked layout and back button are not exposed by the React wrapper.

Pass a `label` and nested menu items to `MenuSubmenu`; it renders and wires the trigger and panel.

<CodeExample>
    <Menu label="Menu button">
        <MenuItem href="#menu-items">Action</MenuItem>
        <MenuItem href="#menu-items">Another action</MenuItem>
        <MenuItem href="#menu-items">Something else here</MenuItem>
        <MenuSubmenu label="More options">
            <MenuItem>Submenu action</MenuItem>
            <MenuItem>Another action</MenuItem>
            <MenuItem>Something else</MenuItem>
        </MenuSubmenu>
    </Menu>
</CodeExample>

## Menu options

Use `offset` to change the location of the menu. A number sets the distance from the trigger in pixels; `[crossAxis, mainAxis]` sets both axes. `padding` sets the viewport inset and `flip={false}` disables collision flipping. The trigger remains the positioning reference.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <Menu label="Offset" offset={[10, 20]}>
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
        <Menu label="No flip" flip={false}>
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
    </div>
</CodeExample>

### Auto close behavior

By default, the menu is closed when clicking inside or outside the menu. You can use the `autoClose` option to change this behavior of the menu.

Regardless of the `autoClose` setting, pressing <kbd>Esc</kbd> while focus is within the menu (its toggle or items) closes the menu and returns focus to the toggle.

<CodeExample>
    <div className="d-flex flex-wrap gap-3">
        <Menu label="Default" autoClose={true}>
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
        <Menu label="Clickable inside" autoClose={'inside'}>
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
        <Menu label="Clickable outside" autoClose={'outside'}>
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>
            <MenuItem href="#menu-items">Something else here</MenuItem>
        </Menu>
        <Menu label="Manual close" autoClose={false}>
            <MenuItem href="#menu-items">Action</MenuItem>
            <MenuItem href="#menu-items">Another action</MenuItem>

        </Menu>

## Accessibility

The [<abbr title="Web Accessibility Initiative">WAI</abbr> <abbr title="Accessible Rich Internet Applications">ARIA</abbr>][5] standard defines an actual [`role="menu"` widget][6], but this is specific to application-like menus which trigger actions or functions. <abbr title="Accessible Rich Internet Applications">ARIA</abbr> menus can only contain menu items, checkbox menu items, radio button menu items, radio button groups, and sub-menus.

Idea React’s menus, on the other hand, are designed to be generic and applicable to a variety of situations and markup structures. For instance, it is possible to create menus that contain additional inputs and form controls, such as search fields or login forms. For this reason, Idea React does not expect (nor automatically add) any of the `role` and `aria-` attributes required for true <abbr title="Accessible Rich Internet Applications">ARIA</abbr> menus. Authors will have to include these more specific attributes themselves.

Submenu triggers are an exception. `MenuSubmenu` adds `aria-haspopup="true"` to its trigger, and keeps `aria-expanded` on it in sync as the submenu opens and closes. The wrapper keeps this state in sync automatically.

### Keyboard navigation

Menus include built-in keyboard support for navigating menu items. Submenu arrow keys remain physical directions in both LTR and RTL; the wrapper does not implement upstream RTL key reversal.

| Key               | Action                                |
| ----------------- | ------------------------------------- |
| `↓` / `↑`         | Navigate to next/previous menu item   |
| `→`               | Enter submenu                         |
| `←`               | Exit submenu and return to parent     |
| `Enter` / `Space` | Activate focused item or open submenu |
| `Esc`             | Close the menu                        |
| `Home` / `End`    | Jump to first/last menu item          |
| `Tab`             | Move focus and close the menu         |

## Usage

`Menu` manages its own open state, trigger wiring, positioning, and cleanup. Do not initialize Bootstrap’s plugin on the same elements.

### Options

| Prop                  | Default        | Description                                                                                                               |
| --------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `autoClose`           | `true`         | Close on inside/outside clicks, only `"inside"`, only `"outside"`, or neither (`false`). Escape still dismisses the menu. |
| `placement`           | `"bottom-end"` | Preferred side and edge alignment; `align` defaults to `"end"`.                                                           |
| `responsivePlacement` | —              | Override placement at named breakpoints.                                                                                  |
| `offset`              | `0`            | Distance from the toggle, or a `[crossAxis, mainAxis]` pair.                                                              |
| `padding`             | `8`            | Inset from the viewport edge when shifting to avoid overflow.                                                             |
| `flip`                | `true`         | Flip to another side when the preferred side lacks space.                                                                 |
