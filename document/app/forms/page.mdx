# Forms

Examples and usage guidelines for form control styles, layout options, and custom components for creating a wide variety of forms.

## Overview

Idea React's form components build on [Bootstrap's form styles][1] and provide a consistent API for rendering controls across browsers and devices.

For further customization, pass a CSS Module class through `className`. The CSS reference sections show custom property defaults from the published stylesheet; Sass-only build configuration is omitted because this site uses compiled Bootstrap CSS.

Be sure to use an appropriate `type` attribute on all inputs (e.g., `email` for email address or `number` for numerical information) to take advantage of newer input controls like email verification, number selection, and more.

Here’s a quick example using the form components. Keep reading for component props, form layout, and more.

<CodeExample>
    <Form>
        <div className="mb-3">
            <FormLabel htmlFor="exampleInputEmail1">Email address</FormLabel>
            <FormControl type="email" id="exampleInputEmail1" aria-describedby="emailHelp" />
            <FormText id="emailHelp" block>
                We’ll never share your email with anyone else.
            </FormText>
        </div>
        <div className="mb-3">
            <FormLabel htmlFor="exampleInputPassword1">Password</FormLabel>
            <FormControl type="password" id="exampleInputPassword1" />
        </div>
        <FormField className="mb-3">
            <Checkbox id="exampleCheck1" />
            <FormLabel htmlFor="exampleCheck1" plain>
                Check me out
            </FormLabel>
        </FormField>
        <Button type="submit" theme="primary" variant="solid">
            Submit
        </Button>
    </Form>
</CodeExample>

## Disabled forms

Set the `disabled` prop on `FormControl` to prevent user interaction and give it a disabled appearance.

```tsx
<FormControl id="disabledInput" type="text" placeholder="Disabled input here..." disabled />
```

Add the native `disabled` attribute to a `fieldset` to disable all nested controls. Browsers treat native inputs, selects, and buttons inside a disabled fieldset as disabled, preventing keyboard and mouse interaction.

This does not disable custom links styled as buttons. Use `Button`'s `disabled` prop for button-like links; it removes navigation and updates keyboard focus and accessibility state.

<CodeExample>
    <Form>
        <fieldset disabled>
            <FormLegend>Disabled fieldset example</FormLegend>
            <div className="mb-3">
                <FormLabel htmlFor="disabledTextInput">Disabled input</FormLabel>
                <FormControl type="text" id="disabledTextInput" placeholder="Disabled input" />
            </div>
            <div className="mb-3">
                <FormLabel htmlFor="disabledSelect">Disabled select menu</FormLabel>
                <FormSelect id="disabledSelect">
                    <option>Disabled select</option>
                </FormSelect>
            </div>
            <FormField className="mb-3">
                <Checkbox id="disabledFieldsetCheck" disabled />
                <FormLabel htmlFor="disabledFieldsetCheck" plain>
                    Can’t check this
                </FormLabel>
            </FormField>
            <Button type="submit" theme="primary" variant="solid">
                Submit
            </Button>
        </fieldset>
    </Form>
</CodeExample>

## Accessibility

Ensure that all form controls have an appropriate accessible name so assistive technologies can convey their purpose. Use `FormLabel` for form controls, or descriptive content for buttons.

When a visible `FormLabel` or button text is not appropriate, provide an accessible name by:

- Pointing to an existing element with `aria-labelledby`
- Providing a `title` attribute
- Explicitly setting the accessible name on an element using `aria-label`

Do not rely on `placeholder` as a control's accessible name; it is only a fallback in some assistive technology and disappears when the control has a value.

While `aria-label` can provide an accessible name, a visible label is generally best for accessibility and usability.

### Variables

Some form variables are set at the root level to be re-used and extended by individual form components, but you’ll most often see variables set at the form control level. Root variables include `--bs-btn-input-*`, which are shared with [buttons][2], and `--bs-control-*` variables.
