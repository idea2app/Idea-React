# Validation

Native constraints (`required`, `type`, `min`, `max`, `pattern`) work without additional JavaScript.
For server feedback, set `validation="valid"` or `"invalid"` and associate messages with
`aria-describedby`; do not rely on color alone.

## Quick start

<CodeExample>
    <Form aria-label="Server validation" noValidate>
        <FormField>
            <FormLabel htmlFor="validationEmail">Email</FormLabel>
            <FormControl
                id="validationEmail"
                type="email"
                defaultValue="invalid"
                validation="invalid"
                required
                aria-describedby="validationEmailError"
            />
            <FormFeedback id="validationEmailError">Enter a valid email address.</FormFeedback>
        </FormField>
        <FormField className="mt-3">
            <FormLabel htmlFor="validationCountry">Country</FormLabel>
            <FormSelect
                id="validationCountry"
                validation="valid"
                defaultValue="ca"
                aria-describedby="validationCountrySuccess"
            >
                <option value="ca">Canada</option>
            </FormSelect>
            <FormFeedback id="validationCountrySuccess" type="valid">
                Looks good.
            </FormFeedback>
        </FormField>
        <FormField className="mt-3">
            <Checkbox
                id="validationTerms"
                validation="invalid"
                required
                aria-describedby="validationTermsError"
            />
            <FormFieldContent>
                <FormLabel plain htmlFor="validationTerms">
                    Accept the terms
                </FormLabel>
                <FormFeedback id="validationTermsError">
                    Please accept before continuing.
                </FormFeedback>
            </FormFieldContent>
        </FormField>
    </Form>
    <FormField className="position-relative mt-3">
        <FormLabel htmlFor="validationTooltip">Username</FormLabel>
        <FormControl
            id="validationTooltip"
            validation="invalid"
            aria-describedby="validationTooltipError"
        />
        <FormFeedback id="validationTooltipError" tooltip>
            Choose another username.
        </FormFeedback>
    </FormField>
</CodeExample>

For browser-default messages, omit `noValidate`. For custom constraint styling, use a MobX-backed
form component that calls the form's `checkValidity()` on submit, prevents invalid submissions,
then passes `validated` to `Form`. `noValidate` suppresses browser messages, not constraint checks.

Validation props also cover textareas, ghost/adorned inputs, radios, switches, ranges, comboboxes,
chips and OTP wrappers. Put feedback after its related control. Tooltips need a positioned ancestor;
inline messages are preferable when screen-reader announcement or persistent feedback is important.
