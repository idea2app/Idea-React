# Popover and tooltip

Small, contextual overlays for displaying information or custom content.

The Idea React [`OverlayBox` wrapper][1] composes Bootstrap 6 tooltip or popover markup with
React-triggered behavior. It supports hover, focus, and click triggers with top, right, bottom, and
left placement.

## Popover

### Overview

Click the button below to show and close a popover.

<OverlayBox
    trigger="click"
    title="Popover title"
    detail="This is the popover content—make it as long as you want."
>
    <Button variant="solid" theme="primary">
        Toggle popover
    </Button>
</OverlayBox>

Things to know when using popovers:

- The React wrapper measures its trigger and content, flips to the roomier side, and shifts inside
  the viewport without a positioning dependency. Resize, scroll and size changes update geometry.
- By default content stays beside its trigger. Set `container` to a selector, an element, or a
  function returning an element to portal elsewhere. Keep overlays used inside modal dialogs
  within the same dialog to preserve top-layer and focus behavior.
- Set `title` for the popover header and `detail` for the body. Without `detail`, the wrapper renders
  a tooltip instead.
- Triggering popovers on hidden elements will not work.
- Popovers for `.disabled` or `disabled` elements must be triggered on a wrapper element.
- When triggered from anchors that wrap across multiple lines, add `.text-nowrap` to keep the panel
  centered on a single line.
- The wrapper removes the panel and its `aria-describedby` reference when it closes or unmounts.
- Popovers can be triggered from an element inside a shadow DOM.
- React escapes text by default. Pass JSX to `title` or `detail` when you intentionally need HTML;
  there is no separate sanitizer option.

The fade animation honors `prefers-reduced-motion`.

### Examples

#### Live demo

Titles are set via the `title` prop and body content is set via `detail`.

<OverlayBox
    trigger="click"
    title="Popover title"
    detail="And here's some amazing content. It's very engaging. Right?"
>
    <Button variant="solid" theme="primary">
        Toggle popover
    </Button>
</OverlayBox>

Use `title` for the popover header, not the native HTML `title` attribute. The wrapper handles the
accessible association with `aria-describedby`.

#### Image content

Pass JSX to `detail` to place rich content, such as an image, inside the popover.

<CodeExample>
    <OverlayBox
        trigger="click"
        title="view info"
        detail={<Image src="https://github.com/idea2app.png" alt="idea2app" />}
    >
        <Button variant="solid" theme="primary">
            {'View'}
        </Button>
    </OverlayBox>
</CodeExample>

Directions are mirrored when using Bootstrap in RTL.

            Popover on top

    <OverlayBox trigger="click" placement="bottom" title="Bottom popover" detail="Bottom popover">

#### Responsive placement

Use `placement` for the default direction and `responsivePlacement` for viewport breakpoints.
The highest matching breakpoint wins.

<CodeCard>
    <OverlayBox
        placement="top"
        responsivePlacement={{ md: 'right', lg: 'bottom' }}
        title="Responsive popover"
        detail="Popover content"
    >
        <Button>Open</Button>
    </OverlayBox>
</CodeCard>

#### Custom container

Pass `container="body"` to escape clipping ancestors, or provide an element or a function returning
one. The wrapper translates viewport measurements into the overlay's positioned ancestor coordinates.
Pointer and focus movement into portal content remain interactive; outside clicks and Escape dismiss it.

<CodeCard>
    <OverlayBox container="body" offset={[0, 12]} padding={8} title="Portal tooltip">
        <Button>Hover or focus</Button>
    </OverlayBox>
</CodeCard>

`offset` is a main-axis distance or a `[crossAxis, mainAxis]` pair. `padding` sets the viewport inset;
`flip={false}` retains the preferred side while still shifting within viewport boundaries.

#### Custom popovers

Customize the appearance with the CSS variables on the panel. Set `overlayClassName` to scope the
overrides, then define the variables on that class:

```css
.custom-popover {
    --bs-popover-header-bg: var(--bs-primary-bg);
    --bs-popover-header-color: var(--bs-primary-contrast);
    --bs-popover-body-color: var(--bs-primary-contrast);
    --bs-popover-border-color: var(--bs-primary-bg);
    --bs-popover-arrow-border: var(--bs-primary-bg);
}
```

<OverlayBox
    trigger="click"
    placement="right"
    overlayClassName={style.customPopover}
    title="Custom popover"
    detail="This popover is themed via CSS variables."
>
    <Button variant="solid" theme="secondary">
        Custom popover
    </Button>
</OverlayBox>

#### Dismiss on next click

Use the `focus` trigger to dismiss popovers on the user's next click of an element other than the
toggle element. **Clicks and focus inside the popover itself do not dismiss it**, so users can select
text or use controls in the content.

Use an `<a>` element with `tabindex="0"` and `role="button"` rather than a `<button>` for proper
cross-browser and cross-platform behavior.

<OverlayBox
    trigger="focus"
    title="Dismissible popover"
    detail="And here's some amazing content. It's very engaging. Right?"
>
    <a tabIndex={0} role="button" className="btn-solid theme-secondary">
        Dismissible popover
    </a>
</OverlayBox>

A shown popover can also be dismissed by pressing <kbd>Escape</kbd>. A popover shown inside a dialog
is dismissed on its own: the first <kbd>Escape</kbd> closes the popover and a subsequent one closes
the dialog.

#### Disabled elements

Elements with the `disabled` attribute aren't interactive, meaning users cannot hover or click them
to trigger a popover or tooltip. Trigger the popover from a wrapper `<div>` or `<span>`, ideally made
keyboard-focusable with `tabindex="0"`.

For disabled popover triggers, you may also prefer a `['hover', 'focus']` trigger so the popover
appears as immediate visual feedback; users may not expect to click a disabled element.

<OverlayBox title="Disabled popover" trigger={['hover', 'focus']}>
    <span tabIndex={0} className="d-inline-block rounded-3">
        <Button variant="solid" theme="primary" disabled>
            Disabled button
        </Button>
    </span>
</OverlayBox>

## Tooltip

### Overview

Hover the button below to see a tooltip. By default, the tooltip appears above its trigger element.

<OverlayBox title="Tooltip on top">
    <Button variant="solid" theme="primary">
        Example tooltip
    </Button>
</OverlayBox>

Things to know when using tooltips:

- The React wrapper uses measured positioning with automatic viewport flipping and shifting,
  so it does not need Bootstrap's JavaScript plugin or Floating UI.
- Tooltips are rendered next to the trigger and removed when closed.
- Provide a title; an empty overlay conveys nothing to users.
- Triggering tooltips on hidden elements will not work.
- Tooltips for `.disabled` or `disabled` elements must be triggered on a wrapper element.
- When triggered from hyperlinks that span multiple lines, add `.text-nowrap` to keep the tip
  centered.
- Tooltips can be triggered from an element inside a shadow DOM.
- The default trigger is both hover and focus, so keyboard users can reach the tooltip.

The fade animation honors `prefers-reduced-motion`.

#### Tooltips on links

Hover over the links below to see tooltips:

    </OverlayBox>

    <OverlayBox title="The last tip!" className="text-nowrap">

    </OverlayBox>

#### Responsive placement

As with popovers, use `responsivePlacement={{ md: 'right', lg: 'bottom' }}` alongside a base
`placement`. Changes apply while the tooltip remains open.

#### Custom HTML

Pass JSX to the `title` prop to control the tooltip markup. React handles escaping and rendering, so
there is no `html` option.

<OverlayBox
    title={
        <>
            <em>Tooltip</em> <u>with</u> <b>HTML</b>
        </>
    }
>
    <Button variant="solid" theme="secondary">
        Tooltip with HTML
    </Button>
</OverlayBox>

With an icon:

<OverlayBox title="Default tooltip" className="text-nowrap">
    <a href="#" aria-label="Hover or focus to see default tooltip">
        <Icon name="bootstrap" size={3} className="fg-primary" />
    </a>
</OverlayBox>

#### Interactive tooltips

Move the pointer onto the tip to reach interactive content inside it, such as a link. The tooltip
stays open while the pointer is over the trigger or the tip. It hides when the pointer leaves both,
or when you press <kbd>Escape</kbd>. This helps satisfy the [WCAG 1.4.13 "Content on Hover or
Focus"][4] success criterion.

<OverlayBox
    title={
        <>
            Read the <a href="https://getbootstrap.com/">full docs</a> for more.
        </>
    }
>
    <Button variant="solid" theme="primary">
        Hover, then move onto the tip
    </Button>
</OverlayBox>

#### Disabled elements

Elements with the `disabled` attribute aren't interactive, meaning users cannot focus, hover, or
click them to trigger a tooltip. Trigger the tooltip from a wrapper `<div>` or `<span>`, ideally made
keyboard-focusable with `tabindex="0"`.

<OverlayBox title="Disabled tooltip" trigger={['hover', 'focus']}>
    <span tabIndex={0} className="d-inline-block">
        <Button variant="solid" theme="primary" disabled>
            Disabled button
        </Button>
    </span>
</OverlayBox>

## Accessibility

Keep popovers and tooltips accessible to keyboard and assistive technology users by only adding
them to HTML elements that are traditionally keyboard-focusable and interactive, such as links or
form controls. While other HTML elements can be made focusable with `tabindex="0"`, this can create
annoying and confusing tab stops for keyboard users. Do not rely solely on `hover` as the trigger,
because it makes the overlay impossible to reach with a keyboard.

Avoid large amounts of content in a tooltip or popover that uses the same `aria-describedby`
association: assistive technologies announce the entire content as one continuous stream. Popovers
do not manage keyboard focus order; if you need interactive content, consider using a
[`Dialog`][2] instead.

## CSS

### Variables

Tooltips and popovers use local CSS variables for real-time customization. Override them through
`overlayClassName` or by targeting `.tooltip` and `.popover` in a scoped style. See the upstream
[popover CSS][3] and [tooltip CSS][4] for the complete variable and Sass map reference.

## Usage

Bootstrap enables popovers and tooltips through a JavaScript plugin. Mount the React component
instead—there is no instance to initialize, retrieve, or dispose:

<CodeCard>
    <OverlayBox title="Popover title" detail="Popover content">
        <Button>Toggle popover</Button>
    </OverlayBox>
</CodeCard>

The wrapper renders the panel, keeps `aria-describedby` in sync, and closes it on outside pointer
interaction or <kbd>Escape</kbd>.

### Props

| Prop               | Type                                                | Default              | Description                                                                |
| ------------------ | --------------------------------------------------- | -------------------- | -------------------------------------------------------------------------- |
| `title`            | `ReactNode`                                         | —                    | Tooltip text or popover header. Required.                                  |
| `detail`           | `ReactNode`                                         | —                    | Popover body. When omitted, the overlay is a tooltip.                      |
| `placement`        | `'top' \| 'right' \| 'bottom' \| 'left'`            | `'top'`              | Side of the trigger where the panel appears.                               |
| `trigger`          | `'click' \| 'focus' \| 'hover'` or an array of them | `['hover', 'focus']` | Interactions that open the panel.                                          |
| `delay`            | `number \| { show: number; hide: number }`          | `0`                  | Delay in milliseconds before showing or hiding.                            |
| `overlayClassName` | `string`                                            | —                    | Extra classes for the tooltip or popover panel, useful for scoped theming. |

### Data attributes

The plugin's data attributes map directly to props:

| Bootstrap attribute    | React prop                                                        |
| ---------------------- | ----------------------------------------------------------------- |
| `data-bs-title`        | `title`                                                           |
| `data-bs-content`      | `detail`                                                          |
| `data-bs-placement`    | `placement` and a `responsivePlacement` breakpoint map            |
| `data-bs-trigger`      | `trigger` (no `manual`; render the overlay conditionally instead) |
| `data-bs-custom-class` | `overlayClassName`                                                |
| `data-bs-html`         | Pass JSX to `title` or `detail`                                   |
| `data-bs-container`    | `container`                                                       |
| `data-bs-offset`       | `offset`                                                          |

### Methods and events

The plugin's `show`, `hide`, `toggle`, `setContent`, and instance methods do not exist in the React
wrapper. Render `<Popover>` or `<Tooltip>` directly when you need to control visibility or content:

<CodeCard>
    <Popover title="Popover title" placement="top">
        Popover content
    </Popover>
</CodeCard>

Likewise, use React state and lifecycle instead of `show.bs.popover`, `shown.bs.tooltip`, and the
other plugin events.
